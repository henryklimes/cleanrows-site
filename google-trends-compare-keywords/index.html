How to compare more than 5 Google Trends keywords on one scale

Google Trends rescales every comparison to 0–100, and the unofficial explore endpoint accepts five terms at a time. Here is the anchor-keyword method, and a hosted option that does the chaining for you.

Two things make "which of these ten keywords is searched more?" harder than it looks.

  1. The unofficial explore endpoint accepts five terms per request. A sixth term is rejected. Google's documentation for the official Trends API alpha says the website now lets you compare eight terms. Past that, you still have to split the list.
  2. Every request has its own 0–100 scale. 100 is the peak of that request, not a global maximum. A 50 in one batch is not a 50 in the next. You cannot paste two CSV exports together and rank them.

The free fix: an anchor keyword

Put the same mid-sized term in every batch. That term is the anchor.

  • Batch 1: notion, jira, asana, trello, clickup
  • Batch 2: notion, basecamp, wrike, airtable

If "notion" averages 64 in batch 1 and 32 in batch 2, batch 2 is on a scale twice as small. Multiply batch 2 by 64/32, then renormalize so the single highest point of all keywords is 100.

def rescale(batches, anchor):
    reference = sum(batches[0][anchor]) / len(batches[0][anchor])
    scaled = {}
    for batch in batches:
        factor = reference / (sum(batch[anchor]) / len(batch[anchor]))
        for keyword, series in batch.items():
            scaled.setdefault(keyword, [v * factor for v in series])
    peak = max(max(series) for series in scaled.values()) or 1
    return {k: [v * 100 / peak for v in series] for k, series in scaled.items()}

Pick an anchor that is neither the most nor the least searched term on the list. Google returns whole numbers. Next to a huge anchor, a small keyword is rounded to 0, and no factor can bring it back. A 0 here often means "too small to measure in this batch", not "no interest". Re-run tiny terms against similar-sized ones instead of reporting them as dead.

You will still get HTTP 429 if you send batches too fast. Space them out; see pytrends 429.

A hosted option

Google Trends API & Scraper – Bulk Keywords, Compare, Trending has a compare mode that sizes the keywords, runs batches of five that share an anchor, and returns one row per term on a shared scale, with a rank column. Keywords still below Google's resolution are flagged with low precision rather than reported as 0. $0.25 per 1,000 keyword-rows.

import os
from apify_client import ApifyClient

client = ApifyClient(os.environ["APIFY_TOKEN"])
run = client.actor("henryklimes/google-trends").call(run_input={
    "mode": "compare",
    "keywords": ["notion", "jira", "asana", "trello", "clickup", "wrike"],
    "geos": ["US"],
    "timeRange": "today 12-m",
})
for row in client.dataset(run["defaultDatasetId"]).iterate_items():
    print(row.get("rank"), row["keyword"], row.get("average_interest"), row.get("precision"))

FAQ

Why can't I just download two Google Trends CSVs and merge them?

Each file is scaled so its own peak is 100. A value of 40 in file A and 40 in file B do not mean the same thing unless the two files share a comparable scale.

How many keywords can the website compare?

Google's Trends API documentation says the website allows comparisons of eight terms. The unofficial explore endpoint that most scripts call still accepts five. In either case you need anchoring once your list is longer than that.

Do the numbers become real search volumes after I rescale?

No. You still have relative interest, just on one shared 0–100 scale. That is enough to rank terms against each other, not to quote monthly searches.
