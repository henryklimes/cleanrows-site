pytrends 429 error (TooManyRequestsError) — causes and fixes

pytrends raises TooManyRequestsError when Google Trends answers HTTP 429. Why it happens, free fixes that still work, and a hosted option if you have to run this on a schedule.

TooManyRequestsError: The request failed: Google returned a response with code 429 is the usual way a pytrends script dies. Google Trends has no generally available public API for this data, so unofficial clients talk to the same endpoints the website uses. Those endpoints rate-limit by IP and by cookie session. Shared cloud IPs (GitHub Actions, Colab, a cheap VPS) get blocked sooner than a home connection.

The popular pytrends library is unmaintained; its GitHub repository is archived and read-only. If a script still works today, pin the version and expect to own the breakage.

What to try for free

  1. Get a normal browser cookie first. Visit trends.google.com in the same session, then call the explore endpoints. Cookieless clients are limited sooner.
  2. Batch at most five keywords per request, which is what the unofficial explore endpoint accepts. Do not fire many payloads in parallel from one IP.
  3. Back off on 429. If the response has a Retry-After header, wait that long. Otherwise use exponential backoff with jitter, then start a new session. Do not treat an empty body as "this keyword has no data".
  4. Cache results. Interest over time barely changes hour to hour. A daily job should not re-fetch a year of history for the same term every few minutes.
  5. Stay off shared datacenter IPs if you can. A laptop or a single dedicated IP, with pauses, is enough for a handful of keywords.

A maintained drop-in such as pytrends-next adds retries and a fresh session for you, but it still uses your IP. If Google keeps answering 429, retries alone will not save a Colab notebook.

FAQ

Why does pytrends throw TooManyRequestsError?

Google's unofficial Trends endpoints rate-limit by IP and session and answer HTTP 429. pytrends raises TooManyRequestsError when it sees that status. Shared cloud IPs hit the limit first.

Will adding retries fix a 429?

Retries help if you also wait, drop the session, and send fewer requests. If the IP itself is blocked, immediate retries make it worse. Wait, cache, and batch up to five terms.

Is there an official Google Trends API I should use instead?

Google opened a Trends API alpha in July 2025. Access is still application-only. If you are not in the alpha, you are left with the website, an unofficial client, or a hosted scraper. See the official Google Trends API page.
