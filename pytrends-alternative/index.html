A pytrends alternative for bulk Google Trends data

pytrends was archived and Google's official Trends API is still an alpha. Here is how to get interest over time, rising queries and comparisons of more than 5 keywords without maintaining a scraper.

pytrends, the unofficial Python library most people used to pull Google Trends, was archived in 2024. It still works some of the time, but it is unmaintained, and Google rate-limits anonymous clients aggressively. Google's own Trends API has been in alpha and is not a general-access product.

If you only need a handful of keywords, the Trends website is enough. If you need hundreds of keywords, a weekly refresh, or a comparison of more than five terms on one scale, you need something that can hold a session, back off on HTTP 429, and retry.

What broke for most pytrends scripts

A typical pytrends script opens an explore request, then calls the four widgets (interest over time, interest by region, related queries, related topics). Google now often:

  • asks for a valid NID cookie from the Trends homepage before the explore call;
  • returns 429 with a Retry-After header after a short burst;
  • sends an empty list for related topics when it thinks the client is a scraper.

Related topics are the fragile one. Treat them as best-effort. Related queries (top, rising, and Breakout) are more reliable.
